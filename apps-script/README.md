# Glow Diary — Apps Script Backend

This is the Google Sheets + Apps Script API layer for Glow Diary.

## 1. Create the Sheet

1. Create a new Google Sheet (or reuse your existing sheet — see **Migrating an existing sheet** below).
2. Rename the tab to `WORK_LOGS` (exact name, case-sensitive).
3. In row 1, add these headers exactly, one per column A–R:

   ```
   id  date  clientName  work  eventType  qty  price  amount  paymentStatus  status  own  referrerName  startTime  endTime  notes  createdAt  updatedAt  clientPhone
   ```

   | Column | Meaning |
   | --- | --- |
   | `id` | unique row id, generated by the script — leave blank when adding rows manually, or use a UUID |
   | `date` | `YYYY-MM-DD` |
   | `clientName` | client's name |
   | `work` | task/service, e.g. "Makeup", "Hair Style", "Saree Draping" — one or more, comma-separated |
   | `eventType` | e.g. "Bridal", "Party" — optional, can be blank |
   | `qty` | quantity/count for this line |
   | `price` | price per unit |
   | `amount` | total for the row (the app auto-fills this as `qty × price`, but you can enter a flat number instead) |
   | `paymentStatus` | `PAID` or `PENDING` |
   | `status` | `WORKED` or `RESERVED` — drives the calendar view |
   | `own` | `TRUE` = direct client work (no referral commission), `FALSE` = work referred by another professional |
   | `referrerName` | name of the referring professional — only meaningful when `own` is `FALSE`, blank otherwise |
   | `startTime` / `endTime` | `HH:mm`, optional — leave blank if not tracked |
   | `notes` | free text (remarks) |
   | `createdAt` / `updatedAt` | ISO datetime, generated by the script |
   | `clientPhone` | client's contact number, optional — powers the tap-to-call button in the app |

   **If you already have a `WORK_LOGS` sheet from before:** just add `clientPhone`
   as a new column R (end of the row) and paste the updated `Code.gs` — no
   other columns move, so nothing else needs to change.

### Migrating an existing sheet

If you already track work in a sheet with columns like `Date, Work, Client, Qty, Price, Total, Remarks, Status, Own`, map them into the new layout:

| Your column | Goes to |
| --- | --- |
| `Date` | `date` |
| `Client` | `clientName` |
| `Work` | `work` |
| `Qty` | `qty` |
| `Price` | `price` |
| `Total` | `amount` |
| `Remarks` | `notes` |
| `Status` (Pending/Paid) | `paymentStatus` (uppercase: `PENDING` / `PAID`) |
| `Own` | `own` (`TRUE`/`FALSE`) |

Columns the app needs that your old sheet doesn't have — fill these in when migrating:
- `id` — leave blank, or generate UUIDs (Sheets: `=UUID()` isn't built in, so leaving blank and running one `getLogs` call after a manual `id` backfill works, or just paste unique text ids)
- `eventType`, `startTime`, `endTime` — leave blank, the app treats them as optional
- `status` — set to `WORKED` for past dates, `RESERVED` for future ones
- `createdAt` / `updatedAt` — set to today's date/time, or leave blank; the script will fill them in the next time that row is edited through the app

Easiest path: duplicate your existing sheet, rename the columns/reorder to match the table above, add the missing columns, then rename the tab to `WORK_LOGS`.

## 2. Add the script

1. In the Sheet, open **Extensions → Apps Script**.
2. Delete the default `Code.gs` contents and paste in the contents of [`Code.gs`](./Code.gs) from this repo.
3. Save the project (e.g. name it "Glow Diary API").

## 3. Deploy as a Web App

1. Click **Deploy → New deployment**.
2. Click the gear icon next to "Select type" and choose **Web app**.
3. Configure:
   - **Execute as:** Me (your account)
   - **Who has access:** Anyone
4. Click **Deploy**, authorize the requested permissions when prompted.
5. Copy the **Web app URL** shown after deployment (looks like `https://script.google.com/macros/s/XXXXXXX/exec`).

## 4. Connect the frontend

In the `glow-diary` frontend project root, create a `.env` file (copy `.env.example`) and set:

```
VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/XXXXXXX/exec
```

Restart the Vite dev server after adding this. Without it, the app runs against an in-memory mock dataset automatically.

## Notes

- Every redeploy of the script (after editing `Code.gs`) requires **Deploy → Manage deployments → Edit → New version** to take effect at the same URL.
- If you change the sheet name or header order, update `SHEET_NAME` / `HEADERS` at the top of `Code.gs` to match.
- **Date/time columns auto-converting:** if you type a date like `2026-08-16` or a time like `17:00` directly into the sheet, Google Sheets will silently convert that cell into a real Date value (it right-aligns instead of left-aligning when this happens). `Code.gs` normalizes these back to plain `YYYY-MM-DD` / `HH:mm` strings on every read, and locks the `date`/`startTime`/`endTime` columns to plain-text format whenever the app writes a row — so this self-heals going forward. If you paste in `Code.gs` for the first time after already having Date-typed cells, just redeploy (**Manage deployments → Edit → New version**) and the next `getLogs` call will read them correctly.
- **Caching:** `getLogs()` (and `getCalendarData`, which is derived from it) is cached via `CacheService` for up to 6 hours, so repeat reads skip the full-sheet scan/sort entirely. Every write action (`createLog`, `updateLog`, `deleteLog`) invalidates the cache immediately, so changes made through the app show up right away. The one gap: if you edit a row **directly in the Sheet UI** (not through the app), that bypasses the cache invalidation — the app will keep serving the cached version for up to 6 hours. If you need an edit to show up immediately after a manual sheet edit, run `invalidateLogsCache()` once from the Apps Script editor (select it from the function dropdown and click Run), or just wait out the cache window.
